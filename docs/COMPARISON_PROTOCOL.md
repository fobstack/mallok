# Mallok 与 Astro 内容站对比协议

- 状态：Accepted claim-gate protocol
- 作用：只决定何时可以把“比 Astro 更简单、更易维护”从产品目标升级为对外证据结论
- 发布关系：不阻塞 Mallok 0.1 产品发布；阻止未经证明的比较宣传

## 1. 预注册与冻结

招募第一位参与者之前，负责人必须把以下内容冻结在一个 clean commit：本协议、两端版本、fixture、任务卡、允许帮助、计时器、概念词典、成功判定、统计脚本和独立 reviewer。开始采集后不得因为结果不理想修改口径；任何协议变更都作废该轮并用新版本重新招募。

测试报告必须公开 protocol commit、Mallok commit/artifact、Astro/Node/package/adapter exact version、OS/硬件、网络条件、原始去标识事件和所有失败/退出样本。

## 2. 参与者与顺序

- 至少 24 人，全部此前未使用 Mallok；
- 12 名内容用户：会使用 Word/Notion/CMS，不使用终端或前端框架；
- 12 名首次技术用户：理解基础文件/终端，但此前未完成 Astro 内容站；
- 每人完成 Mallok 与 Astro 两条路径，形成 paired crossover；
- 每个画像内随机分成 `Mallok → Astro` 与 `Astro → Mallok` 两种顺序，各不少于 6 人；
- 同一个人两条路径之间至少间隔 48 小时，并更换文案但保持 fixture 规模/结构等价；
- 中途退出、超时、账号失败和环境失败都保留在 assigned cohort，不从分母删除。

## 3. 等价输入与目标结果

每条路径使用等价 fixture：

- 一个中文或英文站点标题、描述、Logo 和 5 项导航；
- 5 个普通页面、8 篇文章、12 张本地图片；
- 1 篇 draft、1 个非法 slug、1 张缺 alt 图片作为校验任务；
- 首页、普通页、文章页、404、RSS、sitemap、robots；
- 最终发布到同一 Cloudflare account 级别、同一区域可访问的 HTTPS 结果；
- 默认公开页面不得依赖参与者自行编写客户端 JavaScript。
- 两端最终产物使用同一 Chrome/Lighthouse/PSI 版本、网络配置和采样协议生成 technical SEO、sitemap 与页面性能报告；结果完整公开，但产品易用性实验不把页面性能差异偷换成“更简单”的证据。

Astro 使用测试时官方推荐、功能等价且能完成结果的最短官方路径；允许官方 starter、content collections 和官方 Cloudflare adapter。不得故意选择过时或复杂方案。Mallok 使用正式签名发行物和内置模板，不使用内部调试入口。

## 4. 固定任务

1. 从提供的官方下载页/官方文档开始，安装并得到第一个可编辑预览；
2. 创建站点，导入 fixture 内容/图片并修复给定校验问题；
3. 完成站点信息、导航、模板/外观选择并检查移动预览；
4. 从无 Cloudflare 账号开始，完成账号创建、邮箱验证、条款、连接和首次公网发布；
5. 修改一篇现有文章并让公开 URL 显示新内容；
6. 切换到另一种官方外观，保留全部内容和既有 URL；
7. 处理一次注入的网络中断或授权失效，并到达已恢复或正确升级状态；
8. 导出站点内容/媒体和可托管静态结果。

两端任务卡只描述用户结果，不提示工具内部术语或具体点击/命令。

## 5. 计时与成功边界

- 任务开始：参与者看到任务卡和官方入口、尚未下载工具或打开项目；
- 首次预览结束：指定首页和文章在本机预览中可见且内容正确；
- 首次发布结束：匿名浏览器对指定公开 URL 的 GET 返回正确页面，不能只凭部署命令成功；
- 更新结束：cache-busted 公开 GET 显示指定新内容；
- 恢复结束：公开 GET 正常且参与者能正确说明当前线上状态；
- 安装、下载、账号注册、邮箱验证、条款、授权、网络等待和失败重试都计入 wall-clock；另记录 active time 与 network wait，但不得用后者替换总时间；
- 单任务上限 30 分钟，超过记为失败并保留实际耗时；参与者主动放弃同样记失败。

## 6. 允许帮助

- 允许使用产品内置提示与对应版本的官方公开文档；
- 不允许搜索社区答案、复制预制项目、由维护者操作或使用未公开内部知识；
- moderator 只可重读任务目标和处理人身/设备安全问题；任何流程提示都记录为一次外部求助；
- 需要 moderator 指出下一步后才完成的任务，不计“独立完成”；
- 环境故障只有在两端都无法控制且独立 reviewer 认定时才可标记为 protocol failure，仍保留原始记录。

## 7. 技术概念计数

预注册词典固定包含：terminal/shell、runtime、Node、package manager、dependency、lockfile、component、frontmatter、route、build/build mode、adapter、environment variable、token/secret、Worker、D1/database、binding、migration、deployment target、cache/revalidation。

只有参与者为了继续任务必须理解、选择、输入、编辑或用该概念排错时才计 1；同一概念重复出现仍计 1。纯粹出现在折叠技术详情或未影响操作的页面文字不计。两名盲于产品目标的 reviewer 独立编码；分歧由第三名 reviewer 按预注册词典裁决，并公布一致率。

## 8. 30/90 天维护事件

同一批成功创建的站点保留 90 天。两端在第 30 天和第 90 天执行同样事件：

1. 更新两篇文章并替换一张图片；
2. 新增一个页面和导航项；
3. 切换一次官方外观且保持 URL；
4. 安装测试时最新兼容的安全/bugfix 版本；
5. 处理一次发布凭据失效；
6. 从备份或上一成功版本恢复一次。

记录 active minutes、wall-clock、命令/配置修改、依赖/lockfile diff、失败、求助和开发者介入。未返回、工具不可用或站点不可恢复都按该事件失败和最大时间上限计入，不做 survivor-only 分析。

## 9. 判定与报告

先按全体 24 人报告，再分别报告两个画像；不得只挑有利画像。Mallok 只有同时达到 PRD §11.2 全部阈值，且任一核心任务成功率不比 Astro 低超过 10 个百分点，才能使用限定比较结论。

至少一名没有参与 Mallok 实现、营销或本轮主持的 reviewer 在看到聚合结论前复核：随机化、版本、任务等价、排除项、计时、概念编码、流失处理和统计输出。报告列出所有协议偏差；重大偏差使该轮只能标为探索性结果。

允许的对外结论必须限定范围，例如：

> 在报告所覆盖的博客、知识库和中小企业内容站任务中，Mallok 参与者完成得更快、需要理解的技术概念更少，并在 90 天内花费更少维护时间。

不得由该结果推导“Mallok 在所有网站、性能、灵活性或开发能力上全面优于 Astro”。
