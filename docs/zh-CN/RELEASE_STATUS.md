rc.11 带来插件 API 2 的其余部分——原始请求体路由、动作参数与关联行、插件后台任务和相互隔离的定时钩子——`reference[]` 字段的解析、站点自带的 starter（可附带插件示例数据）、按语言的 tagline、模板可用的 `site.kinds`、询盘表单标签读取主题语言包，以及三项修复：类型的 base 地址返回 500、新站点的占位首页在完成设置后仍被提供、让 Worker 停止的插件任务无限重试。**部署后的第一个请求会执行两条数据库迁移；其余变化见更新日志的升级说明。**

**发布后在线上站点发现、尚未解决：**

- **清除缓存失败时显示成功，且没有日志。** 在测试站上，开关询盘插件和后台的“Clear cached pages”都没有清掉已缓存的页面：按机房采样，点击之后仍在提供三十多分钟前缓存的条目，而后台显示“Cleared the page cache.”。只要发起过清除，后台就显示这句话，不管 Cloudflare 是否真的执行；保存内容、开关插件、修改设置后触发的清除如果失败，也没有任何记录。这两个缺陷在 rc.10 及更早版本中同样存在。已在分支 `fix/purge-failure-reporting` 上修复，**未包含在任何发布版本中**。
- **测试站的清除为什么失败，原因未查明。** 它的令牌和 zone id 已绑定，在 rc.5 上有效；清除请求的响应内容尚未读取。在此之前，“绑定了清除令牌的站点，改动会立即到达访客”这一点对 rc.6 至 rc.11 不成立为已验证事实。

**未在线上验证**，目前只有 Worker 测试和浏览器测试作为依据：

- 插件 API 2 整体。它由测试插件验证过，还没有真实插件在已部署站点上使用过 `renderData`、插件页面、记录面板、内容钩子、原始请求体路由、后台任务或带插件记录的 starter。
- 按语言的 tagline、询盘表单标签读取主题语言包、`site.kinds`、`reference[]` 字段：还没有已部署站点使用。
- 含插件任务的一次定时调用，或一次 starter 导入，在单次调用里的开销。每次最多五个插件任务是判断，不是实测。
- 用 rc.10 搬迁后的 Resend 密钥仍能发出邮件、按插件缓存标签清除、两个限流绑定各自计数。Cloudflare 文档仍未写明 Free 套餐是否包含限流绑定。

rc.6 至 rc.11 均未重新采集 CPU 样本。下文 rc.5 性能数据仅为历史证据，不能作为 rc.11 跑分；`renderData`、保存钩子和插件任务会给当时已超出 10 ms 目标的调用增加开销。维护者接受已测 CPU 限制用于开源及 RC 试用；稳定版验收仍未完成。
