## 3. 原子性前置门

编码前必须先用本地 D1 spike 或已批准 ADR 证明所选 D1 API/SQL 方案满足：CAS 校验、创建 revision、切换 pointer、增加 document version 和写入 idempotency response 全部提交或全部回滚。

不能用“先 SELECT、再由应用决定、最后多次无保护写入”的序列。零行更新也必须触发整批失败，不能把它当作成功。如果项目本地 Wrangler/D1 版本无法证明该语义，立即返回 `BLOCKED`，不得用内存锁或单进程测试伪装数据库原子性。

## 4. 管理 API wire contract

路由全部位于 `/__mallok/api/v1`，不设置 CORS 允许头：

- `GET /documents?limit=&offset=&status=`；
- `GET /documents/:id`；
- `POST /documents/:id/publish`；
- `POST /documents/:id/unpublish`；
- `GET /health`。

所有路由包括 health 都要求 `Authorization: Bearer <token>`。Worker secret 必须是 `hex:` 或 `b64u:` canonical 编码，decode 后为 32–128 raw bytes，并拒绝 padding、非 canonical re-encode 与空白；未配置/格式不合规返回 503 `ADMIN_DISABLED`。官方生成器固定产生 32 个 CSPRNG raw bytes，运行时不得声称能估算熵或维护主观字符串黑名单。比较双方 SHA-256 digest 的全部字节，不记录明文或摘要。

共同响应头：

- `Cache-Control: no-store`、`Pragma: no-cache`；
- `Content-Type: application/json; charset=utf-8`；
- 受限、可追踪的 request id；
- 不返回 CORS wildcard。

稳定错误 envelope：

```json
{
  "error": {
    "code": "PRECONDITION_FAILED",
    "message": "...",
    "hint": "...",
    "requestId": "..."
  }
}
```

错误 code/status 只能使用 `HTTP_API.md` 第 14.1 节完整映射，包括 `PRECONDITION_REQUIRED/PRECONDITION_FAILED`、`REQUEST_BODY_TOO_LARGE`、`ADMIN_DISABLED`、`DEPLOYMENT_IN_PROGRESS` 与幂等错误；不得另造 `VERSION_CONFLICT` 或改变既有语义。

## 5. Publish 请求与响应

必填 headers/body 严格实现 `HTTP_API.md` 第 6～8、11 节：

- publish raw body 上限固定 2,097,152 bytes，在 JSON parse 前按 Content-Length/stream 双重执行；压缩 body 不支持；
- body 通过 `jsonc-parser@3.3.1` 的 strict parse/visitor 处理：comments、trailing comma、多 root 和语法错误全部拒绝；按对象层级维护已解码 property-name set，任何深度的 duplicate key 都返回 `REQUEST_INVALID`。不得先用原生 `JSON.parse` 丢失重复键后再假装已校验；
- `Idempotency-Key` 为 16–200 个允许 ASCII 字符；数据库只保存 hash；
- 首次创建使用且只使用 `If-None-Match: *`；更新使用 GET document 返回的强 `If-Match: "mallok-doc-<id>-v<n>"`；`v0` 不是 wire representation；
- body 直接是严格 `ContentInput` JSON，不加 `schemaVersion/source` wrapper；不接受 trusted HTML/hash/version/server time；path/body id 必须一致；
- 服务端重新规范化输入时间为 `.sssZ` UTC、检查 Worker 内嵌的已部署 asset manifest、编译和计算 hash；draft 返回 422；future publishedAt 可保存但暂不可见；进入 batch 前精确执行 source 262,144 bytes、body 1,048,576 bytes、row 1,500,000 bytes 上限；
- Markdown 图片检查必须调用 T-004 已验收的 `@mallok/core/media` API；Worker 内嵌 manifest 先按 schema/唯一性验证，损坏 manifest fail closed 为内部/部署错误，不能复制 AST/URL 规则或伪装成作者缺图；只有无 issue 的完整结果才把最多 100 个 canonical `{url}` 与 revision 原子持久化；
- 响应 shape、outcome `created|updated|republished|unchanged`、Location/ETag/revision/artifact headers 与 cache-busted URL 完全按 reference；publish/unpublish 的 body `document.etag` 必须等于 `strongDocumentEtag(document.id, document.version)`，并与响应 header 相同，UUID 或 version 任一错配的 OpenAPI/runtime 负例必须失败。相同当前 artifact 不写 revision/pointer/version。

同一 id 改 slug 创建新 revision并原子更新 published pointer 的 slug；`documents` 表本身不保存 slug。新 slug 可见，旧 slug 404。其他 document 占用 slug 时返回 409，不改变任何状态。

## 6. Unpublish 与列表

- unpublish 同样要求 auth、`Idempotency-Key` 和准确 `If-Match`；body 必须零字节且不要求 Content-Type；
- 成功移除 published pointer 并增加 document version，不删除 document/revision；已经 unpublished 的新请求为 no-op、不增加版本；
- `GET /documents` 与 `GET /documents/:id` 必须复用 T-007 的 `AdminDocumentRepository` 单 statement snapshot；实现 limit/offset/status、`limit + 1`/nextOffset、固定排序与强 ETag/304，均不返回 source Markdown 或 body HTML；
- health 只返回服务版本、schema compatibility 和 D1 可访问性，不返回 binding、ID、SQL 或 secret 状态细节。

## 7. 幂等与并发

- request hash 精确使用 `DATABASE.md` 第 10 节的 apiVersion/operation/document/precondition/body canonical shape；
- 同 key + 同 hash 在 24 小时内返回第一次保存的 status/body，不重复编译/写入；
- 同 key + 不同 hash 返回 409 `IDEMPOTENCY_CONFLICT`；
- 过期 key 可以由有界维护操作清理，公开请求不得执行无界 DELETE；
- 过期管理 ETag 返回 412 `PRECONDITION_FAILED` 和安全可公开的 currentEtag，不写 revision/idempotency/pointer；
- 并发相同 expected version 只能有一个成功；
- compiler/schema/options 变化使 artifact 改变并创建新 revision，即使 source 相同。
- 10,000 pointer 满额时，已 published document 的 UPDATE 仍可成功；新/已下线 document 的 pointer INSERT 原子返回 422 `CONTENT_COLLECTION_TOO_LARGE`，无 revision/version/idempotency 部分状态。
- 新 revision 使 256 MiB payload ledger 超限时原子返回 507 `D1_STORAGE_BUDGET_EXCEEDED`，revision/pointer/version/idempotency/ledger 均不产生半状态。
- created/updated/republished/unpublished/no-op/replay 的 system timestamps 必须逐项符合 `DATABASE.md` 第 7.1 节；任何 pointer/CAS/slug 失败连同新 revision、ledger 与时间全部回滚。
- local migration 后存在 `bootstrap-v1` barrier；E2E fixture 必须通过测试专用 deploy-fence port 按正式 conditional statement claim/resolve，不能直接删 row 绕过。active preflight/bootstrap/external/releasing 时，所有新 publish/unpublish（包括新 idempotency key 的 no-op）由 mutation-guard trigger 在同一 batch 原子返回 503 `DEPLOYMENT_IN_PROGRESS` 且零写；已经保存的相同 idempotent replay 仍返回原 2xx。
- 两个本地 D1 client 的交错测试必须证明：publish 先提交则后续 closure 能读到 pointer；fence 先提交则 publish 零写；preflight 过期可接管但旧 id 不能续租/进入 external；external 即使 TTL 数值已过仍硬阻断，错误 lock id 不能 resolve。

## 8. 日志与错误

- 日志字段仅限 request id、method、route template、status、duration、稳定 code、document/revision id；
- 不记录 Authorization、Idempotency-Key 全值、body、source Markdown、SQL、stack 或 D1 row；
- 401 区分缺失/非法只通过稳定 code，不泄露 token 配置；413 在 JSON parse 前返回；415 拒绝错误 content type；
- 未预期错误映射为 500 `INTERNAL_ERROR`；暂时性 D1 不可用映射为 503 `DATABASE_UNAVAILABLE`。外部均无 stack，测试日志可以通过注入 sink 断言脱敏。

## 14. 停止条件

- D1 方案无法证明整个 publish 操作原子回滚；
- CAS 依赖进程内锁、先查再写或零行更新后继续成功；
- 服务端需要信任客户端 HTML/hash；
- token 缺失时路由会开放，或日志无法证明脱敏；
- body 上限只能在 JSON parse 后检查；
- 测试需要远程 D1/Worker、真实 token 或降低约束。
