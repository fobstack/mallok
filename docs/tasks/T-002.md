# T-002：配置、frontmatter 与文件内容仓储

- 状态：Approved after T-001 acceptance
- 阶段：Phase 1B
- 前置任务：T-001 已由审查者标记为 `ACCEPTED`

## 1. 目标

建立 Node 侧的可信配置加载边界和 Markdown 文件内容仓储，把项目目录中的 `.md` 文件稳定转换为 `@mallok/core` 的 `ContentEntry`。本任务不渲染页面、不写输出目录、不实现 CLI 命令。

## 4. 交付范围

### 4.1 `@mallok/cli` Node adapter 基础

创建或补齐 `packages/cli`，但不暴露可执行 bin。它可以使用 `node:fs/promises`、`node:path`、`node:url` 和其他必要 Node 标准库，并依赖 `@mallok/core`。

### 4.2 配置契约

完整实现 `docs/CONTENT_CONFIG.md` 第 2、3 节，不在任务中另造第二份 schema。关键验收包括：

- `site.title/url/language` 必填，description 可选；目录、theme entry、public、output 和 cloudflare 字段/默认值与 reference 完全一致；
- site/content metadata 拒绝 XML 1.0 非法 scalar、lone surrogate 与 forbidden control；slug 额外拒绝 closed Windows device-name set，边界与 OpenAPI 使用同一 corpus；
- `site.url` 的 pathname 固定为 `/`，规范化结果以 `/` 结尾；language 使用 `Intl.getCanonicalLocales`；
- 未知字段是 `CONFIG_INVALID`，不是 warning；
- 配置 default export 必须深度复制为纯数据，拒绝 getter、Proxy、class、函数、symbol 和循环，不能冻结调用方对象；
- 配置文件、managed roots 与已有祖先同时执行词法、realpath、symlink/junction 和双向重叠检查；本任务只验证 output，不创建它；
- schema test 断言 `x-mallok-runtimeConstraints` 存在，并以 project-root escape、managed-root ancestor overlap、symlink/junction 和 nearest-existing-ancestor 反例证明 runtime 不只依赖 regex；
- 已知字段非法使用稳定 error code/hint，同一次操作只加载一次；开发期 cache invalidation 留给 T-006。

### 4.3 frontmatter 与内容文件

- 只递归读取配置内容目录下扩展名大小写不敏感为 `.md` 的普通文件；
- 跳过隐藏文件/目录和符号链接，不读取内容根真实路径之外的目标；
- 按规范化 POSIX 相对路径升序处理，不能依赖目录枚举顺序或 mtime；
- UTF-8 使用 fatal decode；文件第一行必须是 `---`，单文件、frontmatter 和正文尺寸上限严格使用 `CONTENT_CONFIG.md`；
- YAML 使用 1.2 core schema；frontmatter 根必须是普通 mapping；拒绝重复键、anchor/alias、merge、自定义 tag、多文档、非 JSON 值和原型相关危险键；日期保持 string；
- 顶层只接受 `id`、`slug`、`title`、`description`、`draft`、`publishedAt`、`updatedAt`、`tags`、`template`、`data`；自定义字段必须放入 `data`；
- `bodyMarkdown` 来自结束分隔线之后的原文，统一 LF；
- 将结构化输入交给 core 规范化，不在 CLI 复制 UUID、slug、日期或 data 规则；
- 单个文件错误必须带规范化相对路径和稳定 error code；
- 一次扫描聚合全部文件级错误并按路径、字段稳定排序；重复 id/slug 报告涉及的全部文件；
- 返回值和内部快照深度冻结，且不冻结或修改 parser/调用方传入的对象。
- 超过 10,000 个 Markdown 文件聚合为 `CONTENT_COLLECTION_TOO_LARGE`，不得构建截断集合。

## 6. 禁止改动

- `packages/core/**` 的公共契约或安全逻辑；若确需变化，返回 `BLOCKED`
- `packages/cloudflare/**`、`examples/**`、`docs/**`、`.claude/**`
- theme、BuildWriter、页面生成、CLI bin、dev server、D1、部署或 GUI
- Git 历史、真实项目外文件和云端资源

## 7. 依赖与网络权限

- direct runtime dependency 白名单仅增加 `yaml@2.9.0`，用于成熟 YAML 1.2 解析；禁止浮动 range；
- 不允许 `gray-matter`、schema 框架或第二个 YAML/frontmatter parser；delimiter 提取保持小型、显式、受测试；
- 除非负责人明确授权获取上述精确包，否则网络关闭；不得访问 Cloudflare 或其他外部服务；
- 若无法获取该精确版本或其 engine/license 与仓库基线不兼容，返回 `BLOCKED`。

若 lock 尚无该精确包，依赖获取必须作为本任务的 `dependency-only first diff` gate：首个 diff 只包含 `packages/cli/package.json`、`pnpm-lock.yaml`，以及创建空 CLI package/注册 workspace 所必需的最小 manifest 元数据，不得包含功能源码或测试。独立 reviewer 必须先核对精确版本、license、engines、transitive/lifecycle 风险、网络记录和 lockfile diff 并明确批准；只有批准后才能以该依赖基线开始功能编码。

## 10. 停止条件

除全局停止条件外，以下情况返回 `BLOCKED`：

- core 现有输入模型无法表达文档规定的 frontmatter；
- 需要第二个 parser、配置转译器或未批准依赖；
- 无法在不跟随 symlink 的情况下证明内容读取边界；
- 为聚合诊断必须改变 core 已接受的快速失败公共行为；
- 配置默认值与权威文档产生冲突；
- 测试必须依赖 mtime、主机时区或目录枚举顺序。
