## 4. `mallok dev`

### 4.1 网络边界

- 默认 `--host 127.0.0.1`；默认端口 `3000`；CLI `--port` 只接受 1..65535；
- 测试可通过内部 server port 注入使用 `0` 让 OS 分配，但这不是公开 CLI option；
- 非 loopback host 必须由用户显式提供，并在启动前输出可见安全 warning；
- 只有显式 `--open` 可以启动浏览器；默认不打开、不做端口扫描、不暴露目录列表；端口占用返回可操作错误；
- 默认 selection 与 production build 相同；loopback `--include-drafts` 额外包含全部 draft（无视 draft 自身 future `publishedAt`），但仍排除非 draft future；
- `--include-drafts` 与任何非 loopback host 组合必须在创建监听器前失败；该模式所有响应带 `Cache-Control: no-store` 与 `X-Robots-Tag: noindex, nofollow, noarchive`，且 build writer 调用数、正式 output/manifest 写入数均为 0；
- 只接受 GET/HEAD；其他方法返回 405 和 `Allow`；
- Host、URL 和 percent-decoding 异常不得形成文件系统路径。

### 4.2 watch 与重建

- 监听 config、内容目录、theme 入口及其项目内依赖、public/theme assets；
- 使用 100 ms trailing debounce 合并 burst；同一时刻最多一个 build，期间变化在结束后再触发一次；
- 启动时执行完整 build；成功后切换 in-memory/current preview；
- 重建失败时保留最后一次成功页面，终端输出稳定 code/hint；
- 修复后 watcher 自动恢复，不要求重启；
- config 改变后重新加载并安全更新 watch 集合；越界路径不加入 watcher；
- 文件删除、重命名、新增、编辑均有测试；
- 关闭信号和测试 teardown 必须释放 server、watcher、timer 和临时目录。

### 4.3 开发反馈

自动刷新是 FR-009 的必需能力，不是可选增强。实现固定提供仅 dev 的 `GET /__mallok/dev/events` SSE 与 `GET /__mallok/dev/client.js`：成功 HTML dev response 在发送前注入同源 external client；每次成功切换新 generation 后 SSE 发送 `event: reload`，client 触发一次 reload。连接断开必须清理 listener，连续 rebuild 不得重复泄漏 client/server handle。

- 只注入内存中的 dev 响应；不得修改 `dist`、theme 源或 build manifest；
- client 只连接同源 loopback endpoint，不加载第三方脚本；
- production build 与 preview 不包含该路由或脚本；对应 URL 在 preview 为普通 404；
- 构建错误使用可访问的简洁诊断响应，至少包含稳定 code、消息和 hint，不显示绝对路径、堆栈、环境变量或未发布正文；
- 本任务不做品牌视觉设计、复杂 overlay 或客户端框架。

## 5. `mallok preview`

- 只读服务最近成功的 static output，不自动重建；output 或 `.mallok/build-manifest.json` 缺失/不匹配时失败；cloudflare target 不冒充 static preview；
- 默认 `127.0.0.1:4173`，同样支持显式 `--host`、`--port`；
- URL path 只解码一次；拒绝无效 percent、NUL、反斜杠、编码或明文 dot segment；
- `/` 与尾斜杠路径解析为对应 `index.html`；未知路径返回 theme 生成的 `404.html` 和 HTTP 404；
- GET/HEAD 语义一致，HEAD 无 body；
- 为 HTML、CSS、JS、JSON、XML、图片和字体设置显式 MIME，未知类型使用 `application/octet-stream`，所有响应设置 `X-Content-Type-Options: nosniff`；
- 禁止目录列表，设置适合本地预览的 `Cache-Control: no-store`；
- preview 不包含 dev 刷新注入。

## 8. 依赖与网络权限

- 优先使用 Node `http`、`fs.watch` 和现有抽象；不新增 web framework、watcher 或 WebSocket 依赖；
- 若目标平台实测证明 Node watcher 无法满足契约，停止并提交依赖提案，不得自行安装；
- 不联网；测试只访问测试进程创建的 loopback server；
- 不启动需要人工终止的长期 server。所有验证由测试 harness 启动并关闭。

## 11. 停止条件

- 默认需要绑定 `0.0.0.0` 或对外 tunnel；
- watcher 错误会终止进程或覆盖最后成功页面；
- 开发刷新必须改写生产文件或引入客户端框架；
- URL 到文件路径无法在单次解码后证明边界；
- 测试留下活动 server/watcher 或依赖固定端口；
- 需要未批准 watcher/server 依赖或浏览器自动化。
