## 4. 交付范围

### 4.1 Theme API 上下文

从 `@mallok/core/theme` 导出 `THEME_API.md` 第 3 节的精确只读类型：`apiVersion: "0.1"`、`SiteContext`、`PageHeadContext`、`ArticleSummary`、`AssetUrls`、三个 page context、`PageRenderer` 与 `MallokTheme`。不得改名、增删字段或增加分页；MVP 首页固定最多 20 篇。

文章 renderer 只通过 `articleTemplates` 暴露，至少包含 `article`。template 未命中使用 `THEME_TEMPLATE_NOT_FOUND`，不回退。所有 context 深度冻结，时间为 UTC string，不暴露 Date、repository 或 adapter。

三个 renderer 返回完整 `SafeHtml` document；文档级校验逐项执行 `THEME_API.md` 第 5、9 节，并以 `THEME_INVALID`/`THEME_OUTPUT_INVALID` 区分入口与输出错误。

### 4.2 主题安全与确定性

- 普通内容插值继续转义；正文只接受 compiler 产生的 `SafeHtml`；
- `html` 的静态片段和插值严格执行 `THEME_API.md` 第 6 节：禁止 script/style/comment raw-text 文法、动态 tag/属性和歧义状态；
- JSON-LD 只通过完整 `jsonScript`；外部脚本只通过 `externalScript(SafeAssetUrl, closedOptions)`，而 `SafeAssetUrl` 只能由 manifest-backed `assets.theme/public` mint。通用 SafeUrl/string/remote URL 必须在类型与运行时同时拒绝；基础主题不使用外部/内联可执行脚本或 inline style；
- CSS 由 `assets.theme("theme.css")` 引用 `/assets/theme/theme.css`；public 资源由 manifest-backed helper 引用；
- 主题不得读取 Node builtin、环境、文件系统、网络、系统时间或随机数；
- render 调用不得修改 context 或 entry；
- 同一 context 连续渲染字节相同；
- Theme API 继续标记 experimental，直到 Phase 3 接受。

### 4.3 基础主题源模板

基础主题模板放在 CLI starter 专用源码目录，而不是新建独立 theme package。至少包含：

- 首页：站点标题、最多 20 篇文章列表和空状态，不生成分页/tag archive；
- 文章页：title、description、canonical、日期、标签和正文；
- 404：一致的文档结构和返回首页链接；
- `theme.css`：系统字体、响应式正文宽度、可见 focus、语义结构和满足 WCAG 2.2 AA 的基础对比；
- 不引用 CDN、远程字体、追踪器或默认 JS。

视觉品牌细化不属于本任务；基础主题只提供中性、可读、可访问的契约样例。

### 4.4 RSS 与 sitemap

core 提供平台无关纯函数：

- RSS 严格实现 `THEME_API.md` 第 8.1 节：XML declaration、channel `title/link/description/language` 顺序，最多 50 个 item，item `title/link/guid/pubDate?/description?` 顺序，description fallback/省略与固定英文 GMT date formatter；
- sitemap 严格实现第 8.2 节：首页第一且无虚构 lastmod，后接最多 10,000 篇同序文章，`loc,lastmod?` 顺序，lastmod 为 `updatedAt ?? publishedAt` canonical `.sssZ`；
- 两者统一两空格缩进、LF + final LF、XML 1.0 escaping/非法 scalar fail-closed，固定 site/entries/asOf 输出 byte golden；不读取系统时间或 locale；

## 7. 依赖与网络权限

- core direct runtime dependency 白名单仅增加 `parse5@8.0.1`，用于 HTML5 文档重解析和结构校验；不得自研 HTML parser；
- root direct dev dependency 白名单仅增加 `esbuild@0.28.2`，用于 browser-neutral/Worker-compatible bundle gate；T-008 仍用真实 Wrangler bundle 复验；
- 基础 CSS 和 HTML 不使用远程资源；获取上述精确包需要负责人单独批准 npm registry 网络，安装后验证阶段断网。
- 结构化报告中的网络字段必须报告事实：未联网写 `none`；确实访问 pnpm registry 写 `pnpm-registry`，并列出获批的精确安装命令。不得把“允许联网”误写成“已经联网”，也不得在确实联网后仍写 `none`。

若 lock 尚无上述精确包，依赖获取必须作为本任务的 `dependency-only first diff` gate：首个 diff 只包含 `packages/core/package.json`、根 `package.json`、`pnpm-lock.yaml` 及包管理器必需的最小注册元数据，不得包含 renderer、theme、feed 源码或测试。独立 reviewer 必须先核对精确版本、license、engines、transitive/lifecycle 风险、网络记录和 lockfile diff 并明确批准；只有批准后才能以该依赖基线开始功能编码。

## 10. 停止条件

- 必须公开任意字符串到 `SafeHtml` 的构造器；
- 主题需要 Node-only 或 Worker-only API；
- Theme Context 仍需读取隐式时间、repository 或配置模块；
- 基础主题必须引入客户端框架、远程资源或未批准依赖；
- RSS/sitemap 规则与 route planner 或发布过滤不一致；
- 现有权威文档无法决定页面 context 的公共字段。
