## 4. CLI 公共约定

创建 `mallok` bin 和根 workspace 开发脚本。命令实现返回结果/抛出领域错误，只有最外层 bin 设置 `process.exitCode`，不得在业务模块调用 `process.exit()`。

逐项实现 `CLI.md` 第 1～3、5、6 节：全局 option 使用 `--cwd`/`--config`/`--target`/`--as-of`/`--json` 等已冻结名称，配置优先级与 stdout/stderr/JSON envelope 不得另造。退出码严格使用 `0..8` 类别表；内容/主题校验、构建、冲突、认证/网络和缺确认不能合并成另一套数字。

命令实现返回结果/抛出领域错误，只有 bin 设置 `process.exitCode`。JSON 模式 stdout 只有一个 envelope，stderr 保持空；`MALLOK_DEBUG=1` 也必须脱敏。

## 5. 命令范围

### 5.1 `mallok init [directory]`

- 支持 `--name`、`--site-url`、`--language`；非 TTY 必须提供全部站点必填值；
- 目标不存在或为空目录时生成 starter；非空时拒绝；MVP 无 `--force`；
- 生成 `CONTENT_CONFIG.md` 的完整目录、`theme/assets/theme.css`、固定依赖、`.gitignore` 和只有变量名的 `.dev.vars.example`；
- 示例文章使用仓库固定的非 nil canonical UUID v4 和固定内容，不使用执行时钟；
- starter package scripts 至少包含 `mallok`、`build`、`dev`、`preview`、`doctor`；其中 `dev` 与 `preview` 在 T-006 前可以明确报告“not implemented”，`doctor` 必须在本任务真实实现，任何 stub 都不能假成功；
- Phase 1B 的仓库内验收使用 workspace-local CLI；独立安装能力留给 T-012。

### 5.2 `mallok new article [slug]`

- 支持 `[slug]`、`--title <text>`、`--published`；缺少交互终端且必要值不足时返回 usage error；
- slug 交给 core 校验；
- UUID 使用 Node Web Crypto 生成 canonical UUID v4，并写入 frontmatter；测试通过注入 ID generator，不固定生产 ID；
- 文件名为 `<slug>.md`，只写配置内容目录；已存在文件、重复 id/slug 或路径风险时拒绝；
- 新文章默认显式写 `draft: true`，只有 `--published` 才写 false；不自动填 `publishedAt/updatedAt`，不读取 mtime；
- 写入采用 exclusive create，不覆盖并发创建的文件。

### 5.3 `mallok validate`

- 无 file 时扫描全部内容；file 必须在 content root；
- 校验配置、全部内容（包括 draft）、集合唯一性、主题和资源冲突；
- 对包括 draft 与 future 在内的每篇 Markdown 调用 T-004 同一 media extractor/manifest validator；缺失 `/assets/**`、相对图片或其他不允许 URL 即失败。production build 仍只对其 visible set 执行正式输出门；validate 不因当前不可见而跳过内容质量；
- 只读，不写 output、不联网；draft/future 同样完整校验，命令不提供 `--include-drafts`。

### 5.4 `mallok build`

- 使用全局 `--target static` 与 `--as-of <带时区 ISO 8601>`；build 不接受 `--include-drafts`，草稿只在后续 `dev --include-drafts` 预览；本阶段 cloudflare target 明确未实现；
- 未给 `--as-of` 时只在命令开始固定一次当前 UTC，并传给整个 pipeline；
- 输出简洁统计：读取、发布、跳过、文件数和 output；
- `--json` 返回相同结构化字段与稳定 error envelope；
- 构建失败保留旧 output。

### 5.5 `mallok doctor`

检查 Node、pnpm、配置、内容目录、主题、output 权限和 Git ignore。每项返回 `PASS|WARN|FAIL|SKIP` 与稳定 code/hint；存在 FAIL 时退出 8。只读，不创建、不修复、不安装；Phase 1B 不检查 Cloudflare 登录。

## 6. 端到端样例

创建 `examples/basic-blog`，其内容、配置和主题与 starter 契约一致，但不是第二套实现。测试必须通过真实 CLI bin 完成：

1. 初始化空目录；
2. 以固定 `asOf` 构建；
3. 检查首页、文章、404、RSS、sitemap 和 CSS；
4. 检查没有生产 client script；
5. 再构建并比较 manifest；
6. 制造内容错误并证明旧 dist 未变化。

## 9. 依赖与网络权限

- CLI 参数解析优先使用 Node `util.parseArgs`；不新增命令框架、prompt 库或颜色库；
- UUID 使用 Node/Web Crypto；不新增 UUID 包；
- 不新增依赖，不联网，不安装生成的 starter 的外部依赖；
- workspace-local E2E 不得伪装成 npm 消费者测试。

## 12. 停止条件

- 为使 starter 可运行必须依赖全局 Mallok、全局 pnpm link 或未发布包，却没有明确 workspace-local 方案；
- init/new 需要覆盖非空目录或现有文章；
- CLI 业务代码必须调用 `process.exit()` 才能测试；
- JSON 模式无法保持 stdout 机器可读或会输出秘密/堆栈；
- build 在本阶段需要 Cloudflare target、网络或远程资源；
- 端到端测试不能证明自己拥有待清理目录。
