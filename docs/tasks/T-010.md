## 4. Endpoint 与 secret 来源

优先级固定：

1. `--endpoint <url>`；
2. `MALLOK_API_URL`；
3. 缺失则 `CONFIG_INVALID`/usage hint。

生产 endpoint 只允许绝对 HTTPS、无 credentials/fragment；测试仅显式允许 loopback HTTP。token 优先从 `MALLOK_ADMIN_TOKEN`，未来系统密钥链 adapter 可追加；本任务不把 token 放入 config、参数、状态文件或子进程 argv。

HTTP client 精确实现 `CLI.md` 第 7 节：每 attempt `15,000 ms`、response 最多 `2,097,152 bytes`、最多 3 次**总 attempts**，attempt 2/3 固定退避 `250/1,000 ms`；只重试暂时性网络错误或 `502|503|504`。唯一 canonical `Retry-After: 0..5` 替代固定 delay；非法/重复/大于 5（包括 deployment fence 的 60）不自动等待。clock/sleeper/fetch/AbortSignal 可注入，超时/超大分别稳定返回 `REMOTE_TIMEOUT`/`REMOTE_RESPONSE_TOO_LARGE`，并取消 reader。mutation 必须复用完全相同 idempotency key/body；4xx、其他 5xx、无效 schema/JSON 与超大 response 不重试。

## 5. `mallok publish`

语法：

```text
mallok publish <file...> [--endpoint URL] [--dry-run] [--yes] [--json]
```

规则：

- `<file...>` 至少一个且全部位于配置内容目录；不提供 `--all`；全局 `--json` 仍适用；
- 使用 T-002 loader 和 core compiler，不复制解析规则；本地 compile 只用于 diff/早期诊断，服务端仍必须重编译；
- 通过 GET document/list 获得当前 id/version/ETag、published pointer 与 current/latest artifact，再生成稳定计划：`create/update-or-republish/no-op/conflict`。当本地 artifact 既不是 current 也不是 latest 时，API 无法证明它是否存在于更早历史；计划必须合并动作，最终以服务器返回的 `updated|republished` 为事实，不能自行猜测；
- 展示 id、相对文件、动作、旧/新 slug 和 expected version，不显示正文/token；
- `--dry-run` 永不发送 publish mutation；默认先展示计划，交互 TTY 必须明确确认；非 TTY 或 `--json` 缺 `--yes` 时拒绝写入；
- 每个 document 是独立原子操作；批量不是跨 document transaction。继续处理安全的其他项并汇总冲突，不静默覆盖；
- 只有 **published pointer 当前已指向相同 artifact** 时才是 no-op、不调用 mutation；document 已存在但 unpublished 时，即使历史 artifact 相同也必须以完整 document ETag 调用 publish，由服务端返回 `republished` 并恢复 pointer/version+1。首次创建使用 `If-None-Match: *`，其他更新/重发布使用完整 document ETag；每项独立 idempotency key，重试复用 key/body；
- 响应的 id/version/revision/artifact 与 `updated|republished` outcome 必须与请求及服务器事实一致；管理 response header ETag、body `document.etag` 与随后管理 GET 的强 document ETag 必须相同；
- 成功后做 no-store 验证：当前已可见内容使用 API 返回的 `cacheBustedUrl`，公开 response 的 `X-Mallok-Revision/X-Mallok-Artifact` 必须与 publish response 相同；它自己的 ETag 必须是合法的最终 body 弱 ETag `W/"mallok-v1-<hash>"`，不允许与管理强 document ETag比较为“相同”。随后用该**公开弱 ETag** 请求相同 URL，必须得到 304。future `publishedAt` 则先用管理 GET 验证 current pointer/revision，再要求公开 `cacheBustedUrl` 为 no-store 404 且首页/RSS/sitemap 不包含该 URL。两类失败都不得把已提交写成已回滚，只报告“已提交但公开验证失败”。

## 6. 媒体发布门

精确复用 T-004 已验收的 `@mallok/core/media` `extractMarkdownImageReferences` 与 `validateMarkdownImageReferences`；不得在 CLI 或发布域复制 Markdown AST 遍历、路径规范化、schema 或排序规则。CLI 只有在 validation result 无 issue 时继续，并可在 plan 中显示不敏感的 `assetReferences` 数量；超过 100 个本地 asset 与其他 issue 一样阻断。T-010 只实现文件系统/HTTP 适配、摘要与发布编排。MVP 允许：

- 绝对 `https:` 图片 URL；
- `/assets/<safe-path>`，且 path/hash 出现在当前 cloudflare asset manifest；服务端还必须以 Worker bundle 内嵌 manifest 作最终权威检查；

拒绝：

- `http:`、协议相对、data/blob/file/javascript 等 URL；
- `../`、反斜杠、百分号、控制字符；
- 新的相对本地二进制路径；
- 没有 cloudflare asset manifest 时的 `/assets/` 引用；
- 清单中的 path/hash 与当前资源不一致。

读取 `BUILD.md` 定义的 `.mallok/cloudflare/asset-manifest.json` 做本地早期诊断；该本地文件不是远端真相，不能让客户端绕过服务端 embedded manifest。T-011 在成功部署后记录其 hash。本任务测试使用明确 fixture，不伪造真实部署。R2 上传不在范围内。

如果 T-004 的提取或验证 API 不足以完成该流程，立即停止并报告缺少的输入/输出契约；不得在 T-010 新建私有 helper 绕开。

## 7. `mallok unpublish`

语法：

```text
mallok unpublish (--id <uuid> | --file <path>) [--expected-version <n>] [--endpoint URL] [--dry-run] [--yes]
```

- `--id` 与 `--file` 恰一；不接受 slug；先读取 metadata 并显示 id、slug、version/ETag；
- expected version 缺失时只读查询并冻结当前 version；TTY 二次确认，非 TTY/JSON 必须 `--yes`；
- `--dry-run` 永不 mutation；
- 使用准确 If-Match 与 idempotency key；412/409 不重试覆盖；
- 成功后用 preflight 保存的旧 `publicUrl + ?__mallok_rev=<旧 artifactHash>` 做 first-primary/no-store GET，必须为 404；再对首页/RSS/sitemap 使用唯一合法 cache-bust 检查不再包含旧 URL；
- revision 历史保留，不调用 delete。

## 8. 输出与退出码

- 汇总 `created/updated/republished/noOp/conflicts/failed/verified`；
- 数字退出码严格使用 `CLI.md`：成功/no-op 0，validation 3，conflict 5，auth 6，network/partial batch 7，缺确认 8；usage 2，内部 bug 才是 1；
- JSON 模式输出一个对象，包含逐项结果但不含 source/body/token/idempotency key 全值；
- 网络错误 hint 区分“未提交”“提交结果未知”“已提交但公开验证失败”。
