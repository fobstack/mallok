- 状态：产品方向已冻结，实现待开始

- 日期：2026-08-27
- 产品域名：`mallok.dev`

- 计划公开仓库：`JasonYv/mallok`（本地未配置 remote，远端尚未核验）

## 1. 产品定义

Mallok 是一个开源、本地优先、Studio-first 的内容建站产品。用户通过“站点、模板、内容、发布”四个对象完成从创建到持续更新；Mallok 负责吸收框架、依赖、构建、数据库和部署复杂度。

0.1 的产品完成条件不是“引擎或 CLI 可用”，而是不会使用终端的目标用户能够独立获得公开网址并完成一次内容更新。

## 2. 要解决的问题

### 2.1 用户问题

- 创建内容站之前，要先安装开发环境并理解框架术语；
- 选模板、写内容、配置托管和处理失败分散在不同工具；
- 网站交付后，所有者仍依赖开发者更新内容或修复升级；
- 更换模板可能演变成重写项目；
- 发布失败时，工具暴露日志和底层错误，却没有说明线上版本是否安全。

### 2.2 产品机会

把内容网站从“代码工程”变成“可携带的站点数据 + 统一的发布产品”。Mallok 的竞争目标是：在内容站路径上比 Astro 更少步骤、更少概念、更易长期维护。

## 3. 目标与非目标

### 3.1 0.1 目标

1. 用户无需终端或代码配置即可创建、预览和发布内容站。
2. 默认界面只使用站点、模板、内容、发布四个核心概念。
3. 站点不生成需要用户维护的前端工程和每站点依赖树。
4. 支持页面、文章、图片以及 Markdown 导入导出。
5. 提供一个意见明确的官方发布路径，后续文章更新无需理解底层数据库或重新部署概念。
6. 发布提交前失败不改变线上版本；提交后公开验证失败时如实显示已切换/待确认状态，并能从 Studio 重新检查或恢复。
7. 通过真人任务测试证明首次使用和维护成本达到本文件的指标。
8. 自动生成 sitemap、robots、canonical 与统一 SEO metadata，并让官方模板通过冻结的 PageSpeed/Lighthouse 质量门。

### 3.2 非目标

- 通用 Web 应用框架或任意服务端编程环境；
- React、Vue、Svelte 等组件兼容层；
- 0.1 的第三方模板市场、插件系统和多云发布矩阵；
- 多租户 SaaS、团队计费和复杂权限；
- 让普通用户直接编辑数据库、主题代码或部署配置；
- 以 CLI happy path 代替 Studio 产品验收。

## 4. 人物模型

以下人物是产品设计假设，不是已经完成的用户研究结论；0.1 测试需要验证或修正它们。

### 4.1 主要人物：独立内容所有者

会使用 Notion、Word 或常见 CMS，能理解页面、文章和模板，但不会 Node.js、Git 或云部署。目标是独立创建并长期维护自己的博客、知识库或业务官网。

成功标准：无需开发者帮助完成首次发布，并能在几周后回来更新内容。

### 4.2 次要人物：小型团队编辑

负责文章、活动和产品页面，不应拥有基础设施知识。0.1 可以由一人在同一设备维护；多人协作、审核和权限进入 P1。

成功标准：明确知道修改是“仅保存在本地”还是“已经上线”，不会误发布草稿。

### 4.3 支撑人物：服务商与高级操作者

需要交付多个站点、备份数据或接入自动化。他们可以使用 CLI、导出和诊断详情，但这些能力不能渗入主要人物的默认路径。

成功标准：Studio 与 CLI 操作同一种站点数据，不形成两套行为和两套真相。

### 4.4 供给人物：模板作者

围绕稳定的内容和布局能力制作模板。0.1 只交付官方模板；作者工具和分发机制进入 P1。

## 5. 用户心智模型

| 对象 | 包含 | 不包含 |
| --- | --- | --- |
| 站点 | 名称、描述、Logo、语言、导航、公开地址、备份 | 配置文件、路由代码、环境变量 |
| 模板 | 模板选择、预览、颜色、字体、紧凑/舒适密度 | 组件框架、Theme API、依赖安装 |
| 内容 | 页面、文章、图片、草稿、发布时间、SEO | frontmatter、文件路径、UUID、SQL |
| 发布 | 变化摘要、公开网址、发布结果、历史、重试与恢复 | build target、Worker、D1、migration、token |

规则：任何新功能必须归入这四类之一；内部术语只能出现在用户主动展开的“技术详情”中。

0.1 可见设置只有一张表：站点名称、描述、Logo、语言、最多 8 项导航；模板选择、accent color、sans/serif font、compact/comfortable density；内容的 title、slug、description、cover/cover alt、status、publishedAt、tags、SEO title/description。Cloudflare 首发成功后显示平台公开地址，0.1 不提供自定义域名编辑。任何其他布局、SEO 或域名控件都不属于 P0。

## 6. 核心闭环

### 6.1 首次使用

```text
打开 Studio → 创建站点 → 选择模板 → 编辑示例内容
→ 实时预览 → 连接发布服务 → 点击发布 → 获得公开网址
```

### 6.2 日常更新

```text
打开站点 → 编辑内容 → 自动保存到本地 → 查看预览 → 点击发布
```

### 6.3 模板切换

```text
打开模板 → 预览新模板 → 应用 → 检查受影响页面 → 发布
```

内容、媒体和默认 URL 必须保留。模板缺少某项展示能力时，先说明影响，不得静默删除数据。

### 6.4 故障恢复

```text
发布未完成 → 显示线上是否变化 → 给出可执行动作
→ 重试，或恢复上一版本 → 验证公开网址
```

## 7. 0.1 功能范围

### 7.1 P0：产品发布必需

| 能力 | 0.1 要求 |
| --- | --- |
| Studio 分发 | 可安装、可直接启动；正常使用不依赖终端 |
| 站点库 | 创建、打开、重命名、复制、备份和删除本地站点 |
| 可携带站点 | 只保存内容、媒体、设置和模板选择；无每站点依赖 |
| 官方模板 | 至少三个：博客、知识库、企业/产品官网 |
| 站点设置 | 名称、描述、Logo、语言、导航；首发后只读显示平台公开地址 |
| 内容 | 页面、文章、草稿、发布日期、摘要、封面、基础 SEO |
| 编辑器 | 可视化编辑、Markdown 导入导出、图片拖放、自动保存 |
| 预览 | 编辑后无需手动构建即可看到接近线上结果的预览 |
| 官方发布路径 | 浏览器授权、首次资源准备、公开网址、后续内容更新 |
| 发布安全 | 发布前检查、变化摘要、线上验证；切换前失败不改变线上版本，切换后异常可识别并恢复 |
| 历史与恢复 | 查看最近发布记录，恢复到上一成功版本 |
| 静态导出 | 在高级操作中导出可托管的静态目录或压缩包 |
| 高级 CLI | 调用与 Studio 相同的产品能力；不作为默认入口或 Studio 依赖 |
| 官方输出 | 官方模板默认公开页面客户端 JavaScript 为 0 B |
| 搜索发现 | compiler 自动生成 canonical、metadata、`/sitemap.xml` 和 `/robots.txt`；不要求模板或用户维护 SEO 插件 |
| 页面性能 | 受管图片自动优化；三个官方模板通过 `SEO_PERFORMANCE.md` 的 Mallok PageSpeed Gate |

### 7.2 P1：0.1 后优先

- 云端同步、团队、角色与审核；
- 托管媒体库、多宽度 `srcset`、手工裁剪、动画/视频优化和大文件管理；
- 定时发布、草稿预览链接和更完整的版本历史；
- 引导式自定义域名和域名故障检查；
- WordPress、Astro 及批量 Markdown 导入器；
- 多语言、内容集合与自定义字段；
- 模板作者 SDK、模板验证和模板市场；
- 服务商的多站点工作台；
- 其他发布服务商与稳定自动化 API。

### 7.3 延后或拒绝

- 任意第三方代码在 Studio 中执行；
- 最终用户可见的构建模式、数据库模式和云适配器选择；
- 每个站点独立安装框架或主题依赖；
- 在没有等价任务证据时扩张为通用网站框架。

## 8. 功能需求与验收

### FR-01 启动与新建

- 首屏只提供“创建站点”和“打开现有站点”两个主要动作。
- 创建过程最多要求站点名称、站点类型、模板和本地保存位置四个显式选择。
- 创建完成后直接进入可编辑预览，不显示安装日志或脚手架过程。

验收：全新设备上的目标用户不打开终端、不编辑文件即可看到第一个预览。

### FR-02 本地站点与升级

- 站点数据默认保存在本地，并能通过系统文件选择器复制、备份和打开。
- Studio 升级前自动创建可恢复备份；数据格式迁移失败时保留旧数据并阻止写入。
- 站点目录不得包含 `package.json`、`node_modules`、lockfile 或要求用户维护的构建配置。

验收：连续三个 Studio 小版本升级后，受测站点无需逐站点手工修改。

### FR-03 模板

- 模板库显示适用场景、关键页面和真实预览。
- 应用模板前展示站点预览；应用后内容不被删除，既有 URL 默认不变。
- 用户只能调整颜色、sans/serif 字体和 compact/comfortable density；0.1 没有自由布局控件。

验收：对标准测试站点更换三个官方模板，内容与既有 URL 保留率 100%。

### FR-04 内容编辑

- 支持页面和文章列表、按 title/slug/tag 的本地过滤、草稿、发布日期字段和 SEO 字段；0.1 不提供站点全文搜索或定时发布。
- 编辑器支持常用 Markdown 语义，但默认不要求用户看到 Markdown 源码。
- 可视模式与 Markdown 源码模式遵循 [内容编辑器契约](EDITOR.md)；遇到不支持语法不得静默丢失。
- 每次修改自动保存到本地，并独立显示“已保存到本地”和“有变化待发布”。
- 导入失败必须定位到具体内容并允许跳过，不得让整个站点不可打开。

验收：用户可以创建文章、插入图片、预览并关闭重开 Studio，内容不丢失。

### FR-05 预览

- 编辑内容、站点设置或模板选项后自动刷新预览。
- 预览提供桌面和移动视口，但不引入“开发服务器”概念。
- 预览与正式发布使用同一内容和模板规则；差异必须在发布前提示。

验收：主要内容修改在本机可用条件下 1 秒内开始反馈，5 秒内完成可见刷新。

### FR-06 首次发布

- 用户从“发布”页连接唯一官方支持的托管路径；授权通过系统浏览器完成。
- Mallok 内部准备所需资源，不要求用户复制 token、账号 ID 或绑定名称。
- 发布前显示将上线的页面、文章、模板和站点设置变化。
- 只有公开网址通过验证后才能显示“已发布”。

验收：目标用户从本地预览到公开网址，全程零命令、零配置文件编辑。

### FR-07 日常发布

- 内容变化通过一个主要“发布更改”动作上线。
- 用户不选择“重新构建”“数据库同步”或“部署 Worker”。
- 重复发布相同内容应快速返回“没有需要发布的更改”。

验收：单篇文章修改在一次显式发布动作后出现在公开网址，并显示对应完成时间。

### FR-08 发布历史与恢复

- 每次成功发布形成一条用户可读记录：时间、变化摘要和结果。
- 切换前中断/验证失败时线上不变；切换后公开 smoke 失败时显示实际 current/未知状态并提供重新检查或恢复，不得谎称线上未变。
- 用户可以恢复上一成功版本；恢复本身需要确认并生成新记录。

验收：模拟网络中断、授权失效和内容校验失败时，不产生界面声称成功但线上不可用的状态。

### FR-09 静态导出

- 静态导出位于发布页的“高级操作”，不与默认发布路径并列要求选择。
- 导出前执行同样的内容与链接检查，完成后提供目标位置和打开方式。
- 导出物可以直接交给静态托管，但 Mallok 不把第三方上传过程伪装成已经发布。

### FR-10 高级 CLI

- CLI 覆盖批量验证、导入导出、预览和发布自动化。
- CLI 与 Studio 操作同一种站点数据和同一组应用能力。
- Studio 不得通过 shell 调用 CLI，CLI 失败也不能阻断 Studio 默认路径。
- CLI 文档与入口统一标记“高级”，不出现在首次 onboarding。

### FR-11 数据可退出

- 用户可导出页面和文章为 Markdown，并连同媒体和站点元数据生成完整备份。
- 导出不要求在线账号，恢复备份不要求原发布服务仍可用。
- 删除本地站点必须明确说明已发布网站仍然在线。0.1 不自动删除 Cloudflare 资源；文章下线通过一次新 bundle 发布完成。

### FR-12 搜索发现与页面性能

- compiler 为全部 published 200 HTML route 生成一致的 title、description、canonical、Open Graph、Twitter Card、lang 和可直接抓取的正文；模板不维护第二套 SEO 逻辑。
- 自动生成根 `/sitemap.xml` 和 `/robots.txt`；sitemap 只包含 published canonical HTML URL，超过 Mallok route 安全线时确定性分片。
- preview 与 404 不可索引；draft、feed、抓取文件和 asset 不进入 sitemap。
- 本地受管图片发布前自动定向、缩小、清理 metadata 和压缩；内容图片不得依赖用户先掌握图片处理工具。
- 发布前给出可理解的 SEO/性能问题；不能修复的 canonical、broken route、外部/动画内容图片、抓取文件错误和硬资源预算超限会阻断。
- 官方模板按 [搜索与页面性能合同](SEO_PERFORMANCE.md) 运行固定版本、多次采样的 Lighthouse/PageSpeed 验收。

验收：三个模板对同一内容产生相同 canonical URL 集合，sitemap/robots/head 一致；官方 fixture 的 45 次本地 Lighthouse 报告与真实 Cloudflare PSI 证据达到冻结门槛。

## 9. 产品状态模型

### 9.1 本地保存状态

- 正在保存
- 已保存到本地
- 保存失败，需要处理

### 9.2 发布状态

- 尚未发布
- 有更改待发布
- 正在发布
- 已发布
- 发布未完成，线上版本未变化
- 已切换新版本，公开验证失败，可重新检查或恢复
- 需要确认线上状态

本地保存与发布必须同时可见，不能用一个模糊的“已保存”让用户误以为内容已经上线。

### 9.3 文案规则

每条错误首先回答三个问题：发生了什么、线上是否受影响、下一步做什么。默认不显示底层名词和堆栈；技术详情可复制并折叠展示。

具体界面与文案见 [体验规范](EXPERIENCE.md)。

## 10. 非功能需求

### 10.1 易用性

- 默认路径终端命令为 0；
- 默认路径需要编辑的代码或配置文件为 0；
- 首次预览前最多 4 个显式选择；
- 首次发布前不得出现 Node、Git、route、build、Worker、D1、binding、migration、token 等内部术语。

### 10.2 可维护性

- 站点没有每站点运行时依赖和 lockfile；
- Studio 与站点数据格式分别版本化，升级前有备份和失败回退；
- Studio、CLI 和发布适配器共享产品能力，不复制业务规则；
- 模板升级不得静默删除内容或改变 URL。

### 10.3 性能

- 官方模板默认客户端 JavaScript 为 0 B；
- 官方模板不加载远程脚本、样式或字体；受管图片在 bundle 中使用 compiler 优化后的单一公开 asset；
- 公开页面 raw HTML ≤256 KiB、gzip CSS ≤32 KiB、LCP 候选图片 ≤200 KiB，确定性 critical budget ≤500 KiB；普通发布用静态预算检查，不能在用户每次发布时把波动的 Lighthouse/PSI 当内容错误；
- 三模板的 home/page/article 在固定环境连续 5 次 Lighthouse mobile cold run 中，Performance 中位数 ≥95 且任一次 ≥90，Accessibility/Best Practices 每次 ≥95，SEO 每次 100；
- 真实 Cloudflare staging 的 PageSpeed Insights mobile lab 中位 Performance ≥90；CrUX 数据不足记为不可用，不冒充失败或通过；
- 有足够真实用户数据后，LCP ≤2.5s、INP ≤200ms、CLS ≤0.1 按 mobile/desktop 第 75 百分位单独报告；
- 包含 100 篇文章的标准站点，常用编辑操作应即时反馈；
- 单篇内容发布的产品目标为 P95 60 秒内公开可见；
- 公开页面性能不得因 Studio 技术选型而增加运行时代码。

### 10.4 安全与隐私

- 无账号也能创建、编辑、预览和导出；
- 发布凭据使用系统安全存储，不写入站点包或导出物；
- 破坏性远端操作必须明确目标、影响和恢复能力；
- 产品分析和诊断上传默认不作为使用前置条件，采集必须说明并征得同意。

### 10.5 可访问性

- Studio 核心流程支持键盘操作、清晰焦点、屏幕阅读器名称和不依赖颜色的状态；
- 官方模板以 WCAG 2.2 AA 为目标；
- 错误提示出现后焦点移动和播报行为可预测。

## 11. 指标与发布门

以下数字是 0.1 的产品目标，不是当前已取得的结果。

### 11.1 绝对体验指标

| 指标 | 0.1 目标 |
| --- | ---: |
| 首次可编辑预览中位时间 | ≤ 3 分钟 |
| 首次预览成功率 | ≥ 90% |
| 首次公开网址中位时间 | ≤ 10 分钟，包含从无 Cloudflare 账号开始的注册、邮箱验证、条款、账号连接与托管授权 |
| 首次公开发布成功率 | ≥ 90% |

### 11.2 与 Astro 的对比指标

对比采用同等内容、页面、图片、托管目标和最终公开结果；Mallok 与 Astro 分别使用测试时各自最佳官方支持路径。参与者随机交叉顺序，至少覆盖内容用户和首次使用两者的技术用户两类画像，并记录完成率、时间、求助、配置修改和 30/90 天维护工作。任务、计时、允许帮助、概念计数、流失处理和独立复核以招募前冻结的 [对比协议](COMPARISON_PROTOCOL.md) 为准。

Mallok 在受测内容站路径上达到“比 Astro 更简单、更易维护”的内部判定线：

- 核心任务完成率至少高 20 个百分点；
- 首次预览和首次发布中位时间至少低 40%；
- 用户必须理解的技术概念至少少 80%；
- 30/90 天人工维护时间至少低 70%；
- 每站点依赖升级和 lockfile 冲突为 0；
- 任一核心任务成功率不得比对照低超过 10 个百分点。

测试报告必须公开版本、环境、任务、原始结果和失败样本。达标后，比较结论仅限定在报告覆盖的内容站路径。

## 12. 发布判定

只有同时满足以下条件，才能称为 Mallok 0.1：

1. P0 功能全部完成；
2. 无终端用户从安装走到公开网址；
3. 日常更新和一次恢复流程通过真人测试；
4. 默认路径保持 0 命令、0 配置；
5. 站点包不存在每站点前端依赖；
6. 切换前失败不改变上一成功版本；切换后异常能如实识别并恢复；
7. 安全、数据迁移、备份恢复和官方模板可访问性通过验收。
8. sitemap、technical SEO、受管图片和 Mallok PageSpeed Gate 在同一候选 SHA 上通过。

编译器、CLI、静态导出或云端发布中的任意单项完成，都只能算工程里程碑，不能单独发布为产品 0.1。
