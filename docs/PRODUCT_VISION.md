# Mallok 产品愿景

- 产品方向：已冻结
- 文档日期：2026-08-27
- 首个产品版本：0.1
- 计划 GitHub owner：`JasonYv`
- 计划公开仓库：`JasonYv/mallok`

## 1. 一句话定义

**Mallok 是一个开源、本地优先的内容建站产品：选择模板、填写内容、点击发布，就能得到一个可持续更新、无需维护前端工程的网站。**

## 2. 战略判断

内容网站长期被当作前端工程交付。即使工具已经简化了页面开发，站点所有者仍常常需要面对运行时、包管理器、组件、路由、构建模式、云适配器和升级冲突。

Mallok 的机会不是手搓一个更小的 Astro，也不是复制 Astro 的组件生态。它要消除“拥有网站就必须拥有并维护一个前端工程”这个前提。

> Astro 帮开发者构建网站；Mallok 让内容所有者拥有网站。

Mallok 明确以 Astro 作为内容站路径上的对照：目标是在完成同等内容网站时，显著减少用户步骤、技术概念和长期维护工作。这个目标通过任务测试和 30/90 天维护数据验收，而不是通过功能数量证明。

## 3. 核心用户

### 3.1 首要用户

- 会使用文档编辑器，但不会或不想维护前端项目的内容创作者；
- 需要独立维护博客、知识库或官网的顾问、工作室和小企业；
- 负责日常更新，但不应该接触部署基础设施的编辑和运营人员。

### 3.2 次要用户

- 为客户交付内容站，并希望客户能够自行更新的服务商；
- 需要批量操作和自动化发布的高级用户；
- 为 Mallok 提供模板的设计者与开发者。

### 3.3 不服务的用户

Mallok 0.1 不面向复杂 Web 应用、后台系统、电商交易流程或需要自由编写组件和服务端逻辑的团队。此类需求应使用通用框架，而不是把 Mallok 扩张成通用框架。

## 4. 唯一产品模型

用户只需要理解四个对象：

1. **站点**：这个网站是谁、叫什么、有哪些导航和域名。
2. **模板**：网站长什么样，允许调整哪些视觉选项。
3. **内容**：页面、文章和媒体。
4. **发布**：把本地变化变成公开版本，并在失败时恢复。

任何功能都必须归入这四个对象。无法归入时，优先判断它是不是内部复杂度，而不是增加第五个顶级概念。

底层仍然可以有构建器、数据库、版本、缓存、迁移和部署状态机，但默认界面不得要求用户理解它们。

## 5. 产品承诺

### 5.1 Studio 是产品本体

Mallok Studio 是 0.1 的首要交付界面。没有无终端入口，就没有完成 Mallok 0.1。CLI 只是共享产品能力的高级适配器，不能充当 onboarding，也不能成为 Studio 的内部脚本依赖。

### 5.2 默认路径零命令、零配置

从安装到预览、首次公开发布和日常内容更新，用户不输入终端命令，不编辑代码或配置文件，不复制账号 ID、token 或云绑定。

### 5.3 本地优先且可迁移

本地站点数据是用户可控制的资产。没有账号也可以创建、编辑和预览；站点可备份、复制、导入和导出。发布服务商不可用时，本地内容仍然完整。

### 5.4 站点不是前端工程

Mallok 站点包只包含站点数据：内容、媒体、站点设置和模板选择。它不包含每站点依赖树、包管理器锁文件、构建脚本或框架配置。升级 Mallok 不应变成逐站点升级工程。

### 5.5 模板与内容分离

更换模板不迁移内容、不改变内容身份，默认不改变公开 URL。官方模板采用受约束的声明式能力；任意远程代码不能进入普通用户模板路径。

### 5.6 发布是一个可恢复动作

首次发布可以在内部完成托管授权和资源创建，后续更新可以在内部使用数据库同步或重新生成静态输出。用户只看到变化、目标网址、当前结果和恢复动作。

只有公开网址验证成功，界面才能显示“已发布”。切换前失败不得改变线上版本；切换后验证异常必须保留上一完整版本，并如实提供重新检查或恢复。

### 5.7 公开页面默认轻量

Studio 的复杂度不能进入访客页面。官方模板默认输出语义化 HTML 和 CSS，客户端 JavaScript 为 0 B；确需交互时按功能显式增加。

### 5.8 开放但不转嫁复杂度

Markdown 导入导出、静态导出、CLI 和模板作者工具用于迁移与扩展，但它们是高级能力，不是普通用户使用 Mallok 的前置知识。

## 6. 比 Astro 更简单的竞争楔子

Mallok 不与 Astro 比拼组件数量。它只比较同等内容网站的完成成本：

| 维度 | Mallok 的产品要求 |
| --- | --- |
| 首次使用 | 安装 Studio 后直接创建站点，不准备开发环境 |
| 认知成本 | 默认只出现站点、模板、内容、发布 |
| 内容更新 | 编辑后一次发布，不选择构建或运行模式 |
| 模板切换 | 内容和 URL 原地保留，不迁移工程代码 |
| 故障处理 | 说明线上是否受影响，并给出重试或恢复 |
| 长期维护 | 没有每站点依赖升级、lockfile 冲突或框架迁移 |

胜负标准不是“二进制更小”，而是用户更快完成、成功率更高、长期维护时间更少。具体阈值见 [PRD §11](PRD.md#11-指标与发布门)。

## 7. 0.1 成功画面

一个此前没有使用 Mallok、不会终端命令的内容创作者可以：

1. 安装并打开 Studio；
2. 从三个官方模板中选择一个；
3. 填写站点名称并编辑示例内容；
4. 在本地实时预览；
5. 通过浏览器完成一次托管授权；
6. 点击发布并获得公开网址；
7. 修改文章，再次点击发布；
8. 在一次模拟故障中仅靠界面恢复。

只完成编译内核、CLI 或本地 HTML 输出，都不等于完成这个产品版本。

## 8. 非目标

- 不成为 Astro、Next.js、React、Vue 或 Svelte 的兼容层；
- 不创建任意组件生态或让最终用户编写模板代码；
- 不要求用户选择 static、SSR、Worker 或数据库模式；
- 不把 Git、Markdown 文件结构或云平台控制台作为默认管理界面；
- 不在 0.1 构建多租户 SaaS、团队计费或插件市场；
- 不用隐藏数据风险、费用或破坏性操作来伪造“一键”。

## 9. 当前事实与开源计划

截至 2026-08-27，本仓库只有文档，没有已交付的 Studio、CLI 或公开发行版；“比 Astro 更简单”是已经冻结的产品目标，尚不是经过测试的数据结论。

产品计划以开源方式发布到 `JasonYv/mallok`。当前本地仓库没有配置 Git remote，远端是否已创建及其所有权尚未核验，许可证也尚未选择。在这些事项完成前，不应把计划仓库描述为已经公开或已经开源发布。
