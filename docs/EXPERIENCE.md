# Mallok Studio 体验规范

- 状态：0.1 产品体验基线
- 日期：2026-08-27
- 适用范围：Mallok Studio 默认路径

## 1. 体验目标

用户打开 Mallok 时，应觉得自己在管理一个网站，而不是打开了一个开发工具。

体验必须持续回答四个问题：

1. 我正在管理哪个**站点**？
2. 它使用哪个**模板**？
3. 哪些**内容**正在编辑？
4. 哪些变化已经**发布**？

默认界面禁止使用 CLI 命令、文件路径、构建步骤、运行模式和云基础设施作为导航或任务说明。

## 2. 信息架构

### 2.1 Studio 首页

首页只承担站点选择，不创造第五个产品概念。

- 最近打开的站点卡片：名称、缩略图、本地保存状态、公开状态；
- 主要操作：“创建站点”；
- 次要操作：“打开现有站点”；
- 卡片菜单：重命名、复制、备份、在文件管理器中显示、删除本地副本。

不在首页展示仓库、分支、环境、构建任务或数据库列表。

### 2.2 站点工作区

站点内固定四个顶级入口：

| 入口 | 首要任务 | 持久主要动作 |
| --- | --- | --- |
| 站点 | 管理名称、描述、Logo、语言、导航、公开地址和备份 | 保存更改 |
| 模板 | 选择、预览和调整外观 | 应用模板 |
| 内容 | 创建和编辑页面、文章、图片 | 新建内容 |
| 发布 | 查看待发布变化、公开网址和历史 | 发布更改 |

全局右上角同时显示两个状态：“已保存到本地”和“有更改待发布”。二者不能合并。

## 3. 首次使用旅程

### 3.1 欢迎页

主标题：`创建一个真正属于你的网站`

主要按钮：`创建站点`

次要按钮：`打开现有站点`

辅助说明：`内容保存在你的设备上。创建和预览不需要账号。`

不得先要求登录、选择运行时、安装依赖或阅读 Quickstart。

### 3.2 创建站点

创建流程采用单一轻量向导，最多四个显式决定：

1. 站点名称；
2. 用途：博客、知识库、企业/产品官网；
3. 模板；
4. 本地保存位置。

语言根据系统推断并允许修改。站点地址、SEO 和品牌细节可以稍后处理，不阻塞首次预览。

完成按钮：`创建并开始编辑`

创建过程只显示产品进度，例如“正在准备模板”“正在创建示例内容”，不得显示安装包日志。

### 3.3 第一次编辑

创建后直接进入带真实示例内容的内容编辑页：

- 左侧是页面和文章；
- 中间是编辑器；
- 右侧是即时预览；
- 首次引导只指出“编辑这里”“预览这里”“发布在这里”。

不要用空白站点迫使新用户先理解信息结构。示例内容可一键替换或删除。

### 3.4 第一次发布

发布页按以下顺序呈现：

1. 变化摘要；
2. 内容检查结果；
3. 搜索与速度检查；
4. `连接并发布`；
5. 浏览器授权；
6. 产品进度；
7. 公开网址和 `打开网站`。

“搜索与速度检查”只使用三个用户状态：`通过`、`有建议`、`需要处理`。默认摘要说明 Mallok 会自动生成 sitemap、robots、页面标题、分享信息并优化受管图片；普通用户不需要认识 Search Console、Lighthouse、canonical 或图片编码参数。`有建议` 不阻止发布，`需要处理` 必须链接到具体页面、字段或图片。

没有 Cloudflare 账号的用户可以在同一个系统浏览器流程中注册、验证邮箱、接受条款并返回 Studio；Mallok 不把预先准备账号作为产品成功的隐藏条件。第一次授权后，不再要求用户接触账号 ID、密钥或绑定。若托管服务存在费用或限额，必须在授权前以人类可理解的方式说明。

发布进度使用四个用户阶段：

- 正在检查内容
- 正在准备网站
- 正在更新线上版本
- 正在验证公开网址

完成标题：`你的网站已发布`

辅助信息：公开网址、完成时间、此次变化数量。

## 4. 日常内容旅程

### 4.1 打开与定位

Studio 记住上次站点和上次编辑内容。内容列表支持按 title/slug/tag 的本地即时过滤，并分为“页面”和“文章”；0.1 不把它宣传为公开站点全文搜索。草稿、已发布和有更改使用文字加图标，不能只靠颜色。

### 4.2 编辑与保存

- 输入后自动保存本地草稿；
- 正在保存时显示 `正在保存…`；
- 完成后显示 `已保存到本地`；
- 与线上版本不同时显示 `有更改待发布`；
- 使用 Studio 内的“关闭站点/退出 Mallok”时必须等待 backend 确认保存；失败则留在当前页面并给出重试或另存备份。直接关闭浏览器 tab/强制结束进程无法被可靠阻止，下一次打开时恢复到最后一个 backend 已确认的编辑 sequence，并明确提示任何未确认输入风险。

“保存”绝不能暗示“已经上线”。

### 4.3 预览

预览默认与编辑并排，也可以进入沉浸模式。提供桌面和移动两个视口，不提供设备参数面板或开发者控制台。

内容无法预览时，保留上一个成功画面，并在对应字段旁指出问题，避免整屏错误替代用户工作。

### 4.4 发布更新

有变化时，发布入口显示数量，例如 `发布 3 项更改`。点击后先展示摘要：

- 新增了什么；
- 修改了什么；
- 删除或下线了什么；
- 模板或站点设置是否变化。

普通内容更新只需要一次显式确认。删除公开内容、恢复旧版本或下线站点需要单独确认；自定义域名不属于 0.1。

## 5. 模板旅程

### 5.1 选择

模板卡片展示真实站点预览、适用场景和支持的页面能力，不展示包大小、依赖或框架标签。

### 5.2 试用

点击模板先进入“试用预览”，使用当前站点的真实内容渲染，但不立即改变本地站点。用户可以切换桌面/移动视口并查看首页、文章页和普通页面。

### 5.3 应用

应用前给出简短影响说明：

- `你的 12 篇内容和现有网址会保留。`
- `新模板不展示文章封面，但封面数据不会删除。`

主要按钮：`应用这个模板`

应用后形成待发布变化；不会自动上线。

## 6. 发布与恢复旅程

### 6.1 发布页结构

从上到下固定为：

1. 当前状态和公开网址；
2. 待发布变化；
3. 内容、搜索与速度检查；
4. 主要发布动作；
5. 最近发布记录；
6. 高级操作：静态导出、技术详情。

普通用户不需要在发布前选择静态、动态、数据库或云运行模式。

### 6.2 中断和未知状态

窗口关闭或网络中断后再次打开 Studio，发布页必须主动确认线上结果：

- 能确认失败：显示上一线上版本仍在；
- 能确认成功：补记发布记录并显示公开网址；
- 暂时无法确认：显示 `需要确认线上状态`，提供 `重新检查`，不得猜测成功或自动重复破坏性操作。

### 6.3 恢复上一版本

恢复入口位于每条可恢复的成功记录中。确认框必须说明：

- 将恢复到哪个时间；
- 哪些已发布变化会被撤回；
- 本地内容不会被删除；
- 恢复后可以再次发布当前本地版本。

按钮使用 `恢复这个线上版本`，不使用 rollback、revision 或回滚指针等术语。

## 7. 状态语言

### 7.1 站点状态

| 状态 | 主文案 | 可用动作 |
| --- | --- | --- |
| 未发布 | 这个站点还没有公开网址 | 发布网站 |
| 已同步 | 本地内容与线上一致 | 打开网站 |
| 待发布 | 有更改尚未上线 | 查看并发布 |
| 发布中 | 正在更新网站，请保持 Studio 打开 | 取消仅在安全时提供 |
| 提交前失败 | 发布未完成，线上仍是上一版本 | 重试、查看问题 |
| 已切换但验证失败 | 新版本已切换，但公开网址检查失败 | 重新检查、恢复上一版本 |
| 状态未知 | 暂时无法确认线上状态 | 重新检查 |

### 7.2 内容状态

- 草稿
- 已发布
- 有更改待发布
- 计划发布（P1）
- 需要处理

不要使用 pending、dirty、synced、revision 等工程词作为用户标签。

## 8. 错误文案原则

每个错误使用相同结构：

1. **结果**：什么没有完成；
2. **影响**：本地内容和线上版本是否安全；
3. **原因**：用用户能处理的语言说明；
4. **下一步**：最多一个主要动作和一个次要动作；
5. **技术详情**：折叠、可复制，不抢占主界面。

### 8.1 示例

| 场景 | 推荐文案 | 主要动作 |
| --- | --- | --- |
| 网络中断、已确认未切换 | 发布未完成。你的内容已保存在本地，线上仍是上一版本。 | 重新发布 |
| 切换后公开检查失败 | 新版本已切换，但 Mallok 暂时无法确认公开页面正常。 | 重新检查 |
| 授权失效 | 需要重新连接发布服务。线上网站不受影响。 | 重新连接 |
| 标题缺失 | 这篇文章还缺少标题，补充后即可发布。 | 返回文章 |
| 地址冲突 | 两篇内容使用了同一个网址。请选择其中一篇修改网址。 | 查看冲突内容 |
| 图片说明缺失 | 这张图片还缺少给读屏用户使用的说明，补充后即可发布。 | 填写图片说明 |
| 外部图片 | 这张图片来自其他网站，Mallok 无法保证速度或稳定性。请先下载到设备，再选择本地图片。 | 选择本地图片 |
| 动画图片 | 0.1 只能发布静态图片。请换成静态 PNG、JPEG、WebP、AVIF 或 GIF。 | 替换图片 |
| 图片仍然过大 | Mallok 已尝试优化，但这张图片仍然太大。裁剪或替换后即可发布。 | 打开图片 |
| 搜索信息重复 | 多个页面使用了相同的标题或说明，可能让访客和搜索引擎难以区分。 | 查看页面 |
| 站内链接失效 | 有一个链接指向不存在的页面，修复后即可发布。 | 查看链接 |
| 线上状态未知 | 我们暂时无法确认刚才是否发布完成，先不要重复操作。 | 重新检查 |
| 存储接近上限 | 网站可用空间不足，当前发布没有执行，线上版本不受影响。 | 管理内容 |

禁止把 `D1_ERROR`、HTTP 状态码、SQL、堆栈或内部资源名称作为主标题。错误编号只用于支持和技术详情。

## 9. 删除、下线与其他破坏性动作

- 删除本地内容不等于下线；两者必须分别命名；
- 删除本地站点时明确公开网站是否仍在线；
- 下线网站、删除远端数据和恢复旧版必须展示对象与影响；0.1 不提供自定义域名变更；
- 有恢复能力时说明恢复期限，没有恢复能力时要求输入站点名称确认；
- 不把复选框预选为同时删除本地与线上数据。

## 10. 空状态、离线与加载

### 空状态

空状态必须给出与当前对象一致的下一步，例如内容页使用 `创建第一篇文章`，模板页使用 `选择模板`。不使用“暂无数据”。

### 离线

离线时仍可创建、编辑、预览和导出。发布入口显示 `连接网络后可以发布`，不得阻止本地工作。

### 加载

超过 300 毫秒的操作提供即时反馈；超过 2 秒显示正在完成的用户阶段；不展示无上下文的无限 spinner。用户可继续安全操作时，不使用阻塞整屏加载。

## 11. 可访问性与输入

- 四个顶级入口、内容树、编辑器、预览和发布按钮支持完整键盘导航；
- 状态变化通过文字、图标和辅助技术公告表达，不只改变颜色；
- 错误出现后焦点落在错误摘要，字段错误与输入建立关联；
- 模板预览和内容图片需要可编辑替代文本；
- 危险按钮不与主要安全操作相邻，触控目标不小于 44 × 44 CSS 像素；
- 动画遵守系统减少动态效果设置。

## 12. 默认路径禁用词

以下词不得出现在首次创建、编辑、预览和发布主路径：

`Node.js`、`pnpm`、`package.json`、`Git`、`frontmatter`、`UUID`、`route`、`component`、`build`、`target`、`Worker`、`D1`、`binding`、`migration`、`Wrangler`、`token`、`revision`、`CAS`、`ETag`。

它们可以出现在用户主动打开的技术详情、CLI 文档和模板作者文档中。

## 13. 体验验收清单

0.1 每次候选发布必须完整走查：

- 新设备首次启动；
- 创建站点并看到预览；
- 创建、编辑和重开一篇文章；
- 切换模板并确认内容、URL 保留；
- 完成首次公开发布；
- 修改文章并再次发布；
- 模拟网络中断、授权失效、内容错误和状态未知；
- 修复外部图片、动画图片、站内断链和搜索信息重复提示；
- 确认 published 页面、404、robots 与 sitemap 的搜索状态符合 `SEO_PERFORMANCE.md`；
- 恢复上一线上版本；
- 离线编辑与完整备份导出；
- 仅用键盘完成核心闭环；
- 确认默认路径为 0 命令、0 配置、0 禁用词。

体验验收不以开发者知道如何绕过问题为通过标准；目标人物必须只依靠 Studio 中可见的信息完成任务。
